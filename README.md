# CivicPulse

A citizen grievance portal for a municipal corporation. Citizens report civic issues (potholes, water leaks, garbage, streetlights), the system classifies and routes each complaint to a department with a priority and SLA, and officials track it through to resolution with photo proof.

**Live demo:** https://civic-pulse-mauve-sigma.vercel.app

The data shown is demo data modelled on Pune Municipal Corporation wards.

## Features

- **File a complaint** with a title, description, photo and map pin
- **Automatic triage**: department, sub-category, priority and SLA are assigned from the complaint text by a rule-based classifier
- **Duplicate detection** for complaints filed near an existing open one
- **Track a ticket** by ID, with a full status timeline
- **Public feed** with upvotes
- **Map view** of complaints with a density overlay
- **Admin dashboard** for officials to assign, progress and resolve complaints with an after photo
- **Analytics** by department, ward, priority and month
- **CivicBot**, a chat helper for ticket lookups and common questions
- **Citizen feedback** and reopening of resolved complaints

## Running locally

Requires Node.js 20 or newer.

```bash
npm install
npm run dev
```

This starts the frontend on http://localhost:5173 and the API on http://localhost:5000.

## Firebase setup

The app stores everything in Cloud Firestore. To use your own Firebase project:

1. Create a Firebase project and a Firestore database.
2. Put your web app config in `server/firebase.ts`, or set these variables in a `.env` file:

```
FIREBASE_API_KEY=
FIREBASE_AUTH_DOMAIN=
FIREBASE_PROJECT_ID=
FIREBASE_STORAGE_BUCKET=
FIREBASE_MESSAGING_SENDER_ID=
FIREBASE_APP_ID=
```

3. Publish Firestore rules that let the server read and write these collections:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /complaints/{id} { allow read, write: if true; }
    match /images/{id}     { allow read, write: if true; }
    match /analytics/{id}  { allow read, write: if true; }
    match /meta/{id}       { allow read, write: if true; }
  }
}
```

These rules are open to anyone and are meant for demo use only. Do not store real personal data with them.

On first start against an empty database the server writes the demo data automatically.

### Collections

| Collection | Contents |
| --- | --- |
| `complaints` | One document per complaint, keyed by ticket ID |
| `images` | Uploaded before and after photos, served at `/api/images/<id>` |
| `analytics/baseline` | Ward stats, monthly trends and KPI baselines |
| `meta/seed` | Marker so demo data is written only once |

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/api/health` | Server and database status |
| GET | `/api/complaints` | List complaints (filters: department, priority, status, ward, search) |
| GET | `/api/complaints/:id` | One complaint |
| POST | `/api/complaints` | File a complaint |
| POST | `/api/complaints/:id/vote` | Toggle an upvote |
| POST | `/api/complaints/:id/feedback` | Submit a rating |
| PUT | `/api/complaints/:id/status` | Assign, progress or resolve |
| POST | `/api/complaints/:id/reopen` | Reopen a resolved complaint |
| GET | `/api/analytics/overview` | Analytics summary |
| POST | `/api/ai/classify` | Classify complaint text |
| POST | `/api/ai/check-duplicates` | Find nearby similar complaints |
| POST | `/api/ai/chat` | CivicBot |
| GET | `/api/images/:id` | An uploaded photo |

## Deploying to Vercel

```bash
npm run build:api
npx vercel deploy --prod
```

`npm run build:api` bundles the backend into `api/index.js`; run it again whenever server code changes.
